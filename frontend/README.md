# 巷口 Vue 前端

Vue 3 + TypeScript + Vite + Vue Router + Pinia。与 Python Agent、Go 点评共用一个 HttpOnly 登录会话。

2026-10-18 更新：修复任务恢复、社区分页与异步回填、中文输入法发送、成功回答保留及草稿重试状态，补充组件回归测试。完整范围见 [优化记录](../wiki/2026-10-18优化记录.md)。

## 启动

在本目录执行 `npm ci`，然后 `npm run build`。巷口 服务会在 8090 首页优先加载 `dist/index.html`，资源通过 `/web/assets/` 提供。缺少构建产物时自动回退旧页面，旧页面始终可从 `/legacy` 打开。

开发模式执行 `npm run dev`，访问 `http://127.0.0.1:5173/web/`；开发服务器将 `/api` 代理到 8090。`npm test` 验证金额、流式解析、中断、错误处理及组件状态切换。组件测试通过 Vue 编译器和自定义渲染器挂载真实组件，不访问真实业务接口；不能替代浏览器验收。

## 页面

- `#/chat`：聊天、历史会话、逐轮推荐卡片、运行记录、任务恢复、草稿确认。
- `#/shops`、`#/shops/:id`：跨分类搜索、排序分页、店铺详情、商品券、关联探店笔记。
- `#/community`、`#/community/:id`：热门/关注/我的笔记、详情、点赞、关注作者、上传图片和发布。
- `#/orders`：当前账号订单、模拟支付、待支付普通订单取消草稿。
- `#/coupons`：已领取/已支付持有券。
- 左下角账号：登录、退出、跨会话偏好、清除记忆。

## 约束

业务请求经 `xiangkou/web_api.py` 的显式路由转发，浏览器不接触 业务后端登录令牌。来源校验与用户归属校验在服务端；前端隐藏按钮不代替授权。

店铺购买先重新读取店铺/商品，保存用户拥有的选择记录，再进入现有 ActionWorkflow。聊天与目录购买共用过期、价格变动、确认和幂等约束。支付只能由用户点击确认，不提供模型支付工具。

所有笔记正文以文本渲染，不执行来自数据库的 HTML。聊天支持安全的粗体显示；没有使用 `v-html`。

本地图片由点评 Nginx 8080 提供，可通过构建环境变量 `VITE_DIANPING_ASSET_ORIGIN` 修改来源。既有服务 上传目录使用 `xiangkou_UPLOAD_DIR`，Docker 已绑定现有图片目录。PNG/JPEG/WebP 单张 5MB，笔记最多9张。移除上传预览不删除服务器文件；尚无孤立图片清理任务。

尚未实现真实店铺评价、笔记评论、真实支付/退款、店铺实时库存/预约。页面会明确说明这些边界。探店热门列表尚无关键词搜索接口，没有伪造搜索功能。

## 演示代金券管理（v1.11.1）

在店铺详情的「商品券」标签点击「添加演示代金券」，填写标题、金额与规则，可创建普通券（售价0为免费券）或限时秒杀券（附库存、服务时区起止时间）。金额在界面以元输入，精确转换为整数分；确认保存后重新加载当前店铺商品。

这是本地演示管理入口，未实现商家入驻或门店归属体系。Python `XIANGKOU_CATALOG_ADMIN_IDS` 和 既有服务 `xiangkou.catalog-admin-ids` 必须配置相同账号白名单；默认无管理权限。本地配置现启用测试账号1010，以及用户明确授权的账号1012。既有服务 原有新增券接口也进行账号权限与参数校验，不能绕过前端直接匿名添加。

秒杀时间依据能力接口返回的 Go 服务时区填写，页面显示服务时间，避免将宿主机时间误当服务时间。普通券不支持限量库存；限量需求使用秒杀券。

验证：Vue 类型检查/构建通过，前端金额和流式解析共5项测试通过；Python回归156项通过。新增券BFF的金额、时间、来源、权限及字段白名单通过mock验证；浏览器已实际打开并填写表单，本轮没有提交创建商品。
